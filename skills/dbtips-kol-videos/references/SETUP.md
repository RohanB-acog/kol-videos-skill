## Run

```bash
uv run tools/candidates.py --search-name "obstructive sleep apnea syndrome" \
    --out candidates.json --videos videos.json

# one call per video; records accumulate
uv run tools/extract.py <video_id> --search-name "obstructive sleep apnea syndrome" \
    --candidates candidates.json > out/<video_id>.json

uv run tools/validate.py out/<video_id>.json
```

Only records whose `video_type` is `KOL interview` belong in the endpoint
payload. Concatenate their `records` arrays into a bare JSON list and store it
under the `/market-intelligence/kol-videos/` key — no disease wrapper.

## Consumer notes

`kol_name` is the identity key: consumers group records by it, so one person must
appear under exactly one spelling. The candidate stage emits a canonical spelling
for this reason, and the prompt is told to prefer it over anything heard in
auto-captions.

A null `opinion` is valid output. Any consumer that dereferences the field must
guard it; do not drop otherwise-sound records to accommodate one that does not.
